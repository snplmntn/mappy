# Mappy v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a working, offline, QR-joinable indoor navigator for a reconstructed SM Makati. It covers Taglish purpose search, wait-aware multi-stop planning, conversational steering, multi-floor routing and landmark locating, all on an i3 / 8 GB / no-GPU laptop.

**Architecture:**
- One Python FastAPI process holds the map, the routing/planning logic and an in-process e5 embedder. It calls a local `llama-server` (Qwen3-1.7B) only when the rule layer can't resolve a message.
- Phones load a no-build vanilla-JS web app from the same process and keep their own trip state.
- All decision logic is pure and unit-tested. The LLM only proposes structured extractions.

**Tech Stack:**
- Python 3.12: FastAPI, uvicorn, pydantic v2, numpy, onnxruntime, tokenizers, rapidfuzz, httpx, segno, pytest.
- llama.cpp `llama-server` (CPU build b11517).
- Vanilla ES modules + SVG (no Node, no build step).

**Spec:** `docs/superpowers/specs/2026-10-09-mappy-design.md`

**Plan format note (deliberate deviation):** Because of the hackathon clock, test code is given in full, and implementation is given as exact interfaces, algorithms and code for the non-obvious parts. The tests are the contract. UI tasks (12–13) have no automated tests (per the user's testing rules) and are specified by behavior and acceptance checks.

## Global Constraints

- Demo machine: Intel i3 12th gen, 8 GB RAM, no GPU. App RAM about 2 GB. CPU-only everything.
- LLM: Qwen3-1.7B Q4_K_M via `llama-server`, thinking disabled, `--ctx-size 2048`, 1 slot, JSON-schema-constrained output. Timeout **8 s**; busy slot means immediate fallback (no queueing).
- Embeddings: multilingual-e5-small int8 ONNX, in-process; `query: ` / `passage: ` prefixes.
- Rules first: quick chips, single searches and common steering never call the LLM.
- Phones: plain `http://` (not a secure context): no mic, camera, service worker, clipboard or Web Share. `localStorage` is allowed but wrapped in try/catch.
- Web bundle: under 150 KB gzipped; no map library; system fonts; one floor rendered at a time.
- Walking speed 1.2 m/s. Escalator 30 s per floor; elevator 60 s wait + 10 s per floor; bridge uses `seconds` from data (default 60).
- Async errands: drop dwell 3 min, pick dwell 3 min. Cost = `total + 0.5*idle + soft_penalty + 100*late_min`. At most 5 errands; at most 20 000 evaluated combinations, then reduce candidates, then greedy.
- Trip state lives on the phone; the server is stateless. `now` is sent as `"HH:MM"`.
- Data honesty: real store names, reconstructed layout; fictional stalls carry `"fictional": true`.
- Commits: `type(scope): message`; work on branch `feat/v1`; no integration tests; no UI tests.

**API additions vs spec §5 (made here, spec updated in Task 10):**
- `POST /api/plan` takes `{from, now, trip, edits?}` and returns `{plan, trip, changes, question?}`, so taps and chat share one code path.
- `POST /api/route` takes `{from, to:{node}|{place}, options?}` and returns `{legs, walk_min}`, used for single-place routing and find-a-friend.
- `GET /api/qr?data=` returns an SVG, used for share-my-spot.
- Places may carry `"fictional": true`; connectors may carry `"name"` and `"seconds"`.

## Review Focus

1. **A message mentioning a store the mall doesn't have** ("Jollibee" when there's none). The user expects a polite "wala akong nahanap" ("I didn't find anything"), not an empty plan or a 500. *Test added to Task 9:* `test_chat_unknown_store_says_not_found`.
2. **Steering with no trip yet** ("30 mins lang" as the first message). The user expects a gentle "wala ka pang plano" ("you don't have a plan yet"), not a crash in `apply_edits`. *Test added to Task 4:* `test_edit_without_errands_asks`.
3. **Unreachable destination under elevator-only** (an escalator-only link). The user expects a warning, not an exception. *Test added to Task 2:* `test_unreachable_returns_none`, plus planner handling in Task 5: `test_unreachable_candidate_skipped`.
4. **`now` after the deadline, or times past midnight** ("aalis ako ng 6" said at 7 PM). The user expects a warning, and the clock arithmetic must stay sane. *Test added to Task 5:* `test_deadline_already_passed_warns`.
5. **More than 5 errands in one message.** The user expects the first 5 to be planned and the reply to say the rest were left out. *Test added to Task 9:* `test_chat_caps_errands_at_five`.

### Task 2: Router

**Files:** Create `server/mappy/router.py`; Test `server/tests/test_router.py`

**Interfaces:**
- Consumes: `Mall`.
- Produces:
```python
class Router:
    def __init__(self, mall: Mall, elevator_only: bool = False): ...
    def seconds(self, src: str, dst: str) -> float | None        # None if unreachable; cached per source
    def path(self, src: str, dst: str) -> list[str] | None
    def legs(self, path: list[str], stop_index: int, dest_label: str) -> list[Leg]
    def nearest_node(self, floor: str, x: float, y: float) -> str
```

Graph rules:
- Walk edges are bidirectional; seconds = meters / 1.2.
- Escalator: directed edges between consecutive stops, 30 s × |level difference| (minimum 30).
- Elevator: all ordered pairs of stops, 60 + 10 × |level difference|.
- Bridge: consecutive stops, both directions, `seconds` or 60.
- `elevator_only` drops escalator edges.
- Each edge carries `(to, seconds, connector_or_None)`.
- Dijkstra uses heapq; the cache maps `src -> (dist, prev)`.

`legs()`:
- Walk the path and cut a new leg whenever the next node is on a different floor.
- A leg's `path` holds `(x, y)` points on its floor.
- If the leg ends at a connector edge: `instruction = f"Take {name} {'↑' if up else '↓' if down else '→'} to {floor_name}"` and `connector = {"id", "kind", "name", "to_floor"}`. For a bridge, use "Cross {name} to {floor_name}". "Up" means the target floor's level is higher.
- The last leg's instruction is `f"Walk to {dest_label}"`.

**Files:** Create `server/mappy/planner.py`; Test `server/tests/test_planner.py`

**Interfaces:**
```python
SHOP = {"clothing", "shoes", "accessories", "gift", "beauty", "home", "department_store", "books_stationery", "electronics", "appliances", "gaming"}
def plan_trip(trip: Trip, start_node: str, now_min: int, router: Router, mall: Mall) -> Plan
```
Algorithm (exact):
1. `active` = errands with status ≠ done. Tokens:
   - todo + async → `("drop", e)`, `("pick", e)`;
   - dropped → `("pick", e)` only, with `ready = ready_at or dropped_at + duration`;
   - sync → `("visit", e)`.
2. Candidates per errand: `[chosen]` if chosen, else `candidates[:k]` with k=3. Remove candidates unreachable from `start_node`. An errand with none left is skipped with the warning `f"Hindi maabot ang {label}"` ("can't reach {label}").
3. `n_perm` = count of valid permutations (estimate as `len(tokens)! / 2**n_async_todo`); `n_assign` = product of candidate counts. While `n_perm*n_assign > 20000` and `k > 1`: decrease k. If still above (permutations alone), use greedy: repeatedly choose the feasible next token with the smallest `walk + idle`.
4. Valid permutation: drop before pick of the same errand; order rules (`first` means the errand's first token at index 0; `last` means its last token at the end; `before`/`after` compare first tokens).
5. Simulate:
   ```python
   t = now; pos = start; walk = idle = 0; ready = {}
   for kind, e in seq:
       place = assign[e.id]; w = router.seconds(pos, mall.places[place].node) / 60
       t += w; walk += w
       if kind == "pick":
           r = ready_at_override(e) or ready[e.id]
           if t < r: idle += r - t; t = r
           t += 3
       elif kind == "drop":
           t += 3; ready[e.id] = hhmm(e.ready_at) if e.ready_at else t + e.duration_min
       else: t += e.duration_min
       pos = mall.places[place].node
   soft = 3 * (number of (i<j) pairs where seq[i] is a SHOP visit and seq[j] is a food/cafe visit)
   late = max(0, t - deadline) if deadline else 0
   cost = (t - now) + 0.5*idle + soft + 100*late ; tie-break by walk
   ```
6. Stops carry times (rounded ints) and reasons:
   - `drop` at index 0: `f"Drop off first — {label} takes {dur} min{src}"`; other drops: `f"Drop off — ready by {hh:mm}"`.
   - `pick`: `f"Pick up — ready by {hh:mm}"`.
   - Visit while any drop is pending (dropped, not yet picked): `"Eat while waiting"` for food/cafe, else `f"{label} while waiting"`.
   - SHOP visit after a food visit: `"Shop after eating"`.
   - Otherwise: `label`.
   - `src` = `" (sabi mo)"` if `duration_source == "user"`.
7. `legs`: for each stop i, `router.legs(router.path(prev_node, node), i, place_name)`. Skip empty paths (same node).
8. Warnings: if late > 0: `f"Hindi aabot ng {deadline}. Tanggalin ang {label of longest visit}?"` ("Won't make it by {deadline}. Remove the {label}?"). If `now ≥ deadline`: `f"Lampas na sa {deadline}."` ("It's already past {deadline}.")
9. `finish_at = min_to_hhmm(t)`. With no active errands, return an empty plan whose finish is now.

`parse` order:
1. **Locate:** a cue present and `search.names_in(msg)` non-empty → `Extraction(intent="locate", landmarks=names, floor=floor_hint(msg))`.
2. **Steering**, only when `trip.errands` is non-empty. Collect edits from every matching pattern:
   - duration → `set_duration`, with `errand` = the first category/label word found in the message, else None;
   - `ready (daw|na)? (by|ng|sa|at)? <time>` → `set_ready_at`;
   - `(aalis|umalis|uuwi|leave|alis) ... <time>` or `(by|bago mag) <time>` with "kailangan" → `deadline`;
   - `(wag na|huwag na|skip|cancel|tanggal(in)?)\s+(yung|ang)?\s*(.+)` → `remove` with the text ref;
   - `(.+?)\s+muna\b` or `\bfirst\b` → `order first`;
   - `(naiwan|iniwan|na-?drop|dinrop|binigay|naipaayos)` → `status dropped`;
   - `(nakuha ko na|tapos na|done na|picked up)` → `status done`;
   - `(stroller|wheelchair|pwd|senior|elevator lang|bawal escalator)` → `elevator_only true`.

   If any edits were found → `Extraction(intent="edit", edits=...)`.
3. **Simple find**, when there's no multi-errand separator (`,`, ` tapos `, ` and `, ` at `, ` then `, ` saka `, ` pati `):
   - `alias_category(msg)` → `Extraction(intent="find", errands=[ErrandReq(query=msg, category=cat)])`;
   - or the message is at most 4 words → find with no category.
4. Otherwise None (go to the LLM).

### Task 7: Locator

**Files:** Create `server/mappy/locator.py`; Test `server/tests/test_locator.py`

**Interfaces:**
```python
def locate(mall: Mall, search: Search, landmarks: list[str], floor: str | None = None) -> tuple[list[Candidate], str | None]
```
Algorithm:
- `inst[name]` = `search.place_ids_named(name)`, or else the top 2 of `search.search(name)` if the fused score is ≥ 0.5.
- Floors = floors of all instances (filtered by `floor` if given).
- For each node on those floors that is not a connector stop:
  - For each landmark: if it has instances on that floor, d = min distance in meters to their rect centers, plus 40 if d > 25. Otherwise 60.
  - Sum the landmark scores.
- Sort ascending. Greedy-merge nodes within 8 m of an already kept candidate. Keep the top 3.
- `ask`:
  - `"floor"` if the kept candidates span more than one floor and the second score ≤ first × 1.15 + 1;
  - `"more_landmarks"` if fewer than 2 landmarks and more than one candidate;
  - else None.
- If no landmark resolves: `([], "more_landmarks")`.

class LLMBusy(Exception): ...
class LLMError(Exception): ...
class LLMClient:
    def __init__(self, base_url: str, categories: list[str], timeout_s: float = 8.0, cache_size: int = 256)
    async def extract(self, message: str, trip: Trip) -> Extraction   # raises LLMBusy / LLMError / asyncio.TimeoutError
    async def health(self) -> bool
SEPARATORS = r",|\btapos\b|\band\b|\bat\b|\bthen\b|\bsaka\b|\bpati\b|\bpagkatapos\b"
def fallback_extract(message: str, trip: Trip) -> Extraction

- `extract`: if `self._lock.locked()` → raise `LLMBusy` (no queue). Under the lock, `asyncio.wait_for(post, timeout)`. Request body:
  ```json
  {"messages":[{"role":"system","content":SYSTEM_PROMPT},{"role":"user","content":"TRIP:\n{summary or 'none'}\nMSG: {message} /no_think"}],
   "temperature":0,"max_tokens":200,"cache_prompt":true,
   "chat_template_kwargs":{"enable_thinking":false},
   "response_format":{"type":"json_schema","json_schema":{"name":"x","schema":SCHEMA}}}
  ```
  `SCHEMA` uses short keys: `{"i": enum[find,plan,edit,locate,other], "e": [{"q": str, "c": enum[categories]|null}] (maxItems 5), "d": [{"op": enum, "e": str|null, "n": int|null, "t": str|null, "r": enum[first,last]|null, "s": enum[dropped,done]|null, "q": str|null}], "l": [str], "f": str|null}`. Map short to long keys into `Extraction(source="llm")`.
- `SYSTEM_PROMPT` is fixed text: the role, the field meanings, the categories list, and 4 few-shot examples covering multi-errand Taglish, steering, locate and other. It must be byte-identical across requests so the prompt cache works.
- LRU cache keyed by `(message.strip().lower(), summary)`.
- `fallback_extract`: if a trip exists and the message has duration words → handled earlier by rules, so here: split on `SEPARATORS`, strip filler words (`ko|ako|yung|ng|na|lang|daw|muna|mag|ma|papa|pa`), drop empty chunks, cap at 5. Return `plan` if 2+ chunks else `find`, with `source="fallback"`.

### Task 9: Chat orchestration service

**Files:** Create `server/mappy/chat.py`; Test `server/tests/test_chat.py`

**Interfaces:**
```python
class Extractor(Protocol):
    async def extract(self, message: str, trip: Trip) -> Extraction
@dataclass
class ChatService:
    mall: Mall; search: Search; router: Router; router_elev: Router; llm: Extractor | None
    def start_node(self, at: dict | None) -> str          # {"anchor":id}|{"node":id}|None -> node (None: first anchor)
    def make_errand(self, query: str, category: str | None, new_id: str) -> Errand | None
    async def chat(self, message: str, at: dict | None, now: str, trip: Trip) -> dict   # {"reply","result","trip"}
    def plan(self, at, now, trip, edits: list[Edit]) -> dict                            # {"plan","trip","changes","question"?}
    def route(self, at, to: dict, elevator_only: bool) -> dict                           # {"legs","walk_min"}
```
`make_errand`:
- Use `search.by_category(category)` if a category is given and has places, else `search.search(query, category)`.
- Keep results within 0.06 of the best score, at most 3. Return None if empty or the best fused score is < 0.35 (HashEmbedder scale; E5 is tuned in Task 8 via the eval).
- `category` = that of the first candidate; duration/async from `mall.service_for(first)`; `duration_source="store"` if the place has a `service` field, else `"default"`.
- `label` = `CATEGORY_LABELS.get(category)` or `query.capitalize()`.

`chat` flow:
1. `x = rules.parse(...)`. If None → try `await asyncio.wait_for(llm.extract(...), 8.5)`; on `LLMBusy | LLMError | TimeoutError | httpx errors` → `fallback_extract`.
2. `find` → result `{"type": "places", "query", "places": [{"id", "name", "floor", "floor_name", "walk_min", "fictional"}]}` (top 5, sorted by score). If empty → text "Pasensya, wala akong nahanap para sa “{q}”." ("Sorry, I didn't find anything for …").
3. `plan`:
   - Build errands with `make_errand` (cap 5; if more were asked, note "Hanggang 5 lang muna" ("Only up to 5 for now")).
   - Unmatched queries are listed in the reply.
   - Append to `trip.errands` (new ids), then `plan_trip`.
   - Reply: `f"Ayos! {n} stops, tapos ka by {finish}."` ("Okay! {n} stops, you'll be done by {finish}.")
   - Result `{"type": "plan", "plan", "changes": []}`.
4. `edit` → `apply_edits`. A question → `{"type": "text"}` with the question as `reply`. Else re-plan. Reply `"Updated!"` with the result `{"type": "plan", "plan", "changes"}`.
5. `locate` → `locator.locate`. Result `{"type": "locate", "candidates", "ask"}`. Reply by ask:
   - None: "Ito ba ang lugar? Pindutin ang tamang pin." ("Is this the spot? Tap the right pin.")
   - floor: "Anong floor?" ("Which floor?")
   - more_landmarks: "May iba pang nakikitang store?" ("Any other stores you can see?")
6. `other` → text help: `"Sabihin mo lang ang kailangan mo — hal. “papaayos ng phone, tapos kain”."` ("Just tell me what you need, e.g. …")
7. Uses `router_elev` when `trip.constraints.elevator_only`. Always returns the updated `trip`, serialized `by_alias=True`.
